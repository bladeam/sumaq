Visión General

¿Por qué existen las Bases de Datos?

❌ El Pasado: Archivos Tradicionales

Archivos de texto o Excel dispersos provocaban:

  • Redundancia e inconsistencia de datos.
  • Dificultad para acceder a la información.
  • Aislamiento de datos y falta de seguridad.

✅ El Presente: Sistemas de BD

Un enfoque centralizado e inteligente que brinda:

  • Integridad y consistencia en todo momento.
  • Independencia entre datos y programas.
  • Seguridad y acceso concurrente multiusuario.
💡 Haz clic para ver un ejemplo del mundo real
Ejemplo: Imagina un banco donde se registre tu saldo en un archivo TXT. Si realizas un retiro en el cajero y al mismo tiempo realizas una compra online, ¡un archivo tradicional fallaría! Una Base de Datos gestiona esto con transacciones seguras.
Unidad I

Arquitectura de un SGBD

Un Sistema Gestor de Bases de Datos (SGBD) es el software que actúa como intermediario entre los usuarios y los datos.

Nivel Externo

La vista personalizada para cada usuario o aplicación.

Nivel Conceptual

Lo que se almacena: La estructura global y las relaciones entre entidades.

Nivel Interno

Cómo se almacena físicamente en el disco duro o servidor.

Lenguajes Clave

DDL (Data Definition Language): Define estructuras | DML (Data Manipulation Language): Consulta y modifica datos.

Unidad I

Álgebra Relacional: La Lógica Matemática

No le temas a la matemática: el Álgebra Relacional es simplemente la base teórica para saber realizar consultas eficientes.

Operaciones Operativas

Selección (σ): Filtra filas de una tabla.

Proyección (π): Filtra columnas específicas.

Operaciones de Conjuntos

Unión (∪), Intersección (∩), Diferencia (−) y Producto Cartesiano (×).

❓ Pregunta rápida: ¿Por qué es útil esto?
Porque antes de escribir código SQL en una computadora, debes ser capaz de razonar cómo filtrar y unir información lógicamente. ¡El motor del SGBD usa exactamente esta lógica internamente!
Unidad II

Diseño Conceptual: El Modelo Entidad-Relación

Antes de programar, debemos diseñar el plano de la base de datos.

Entidades

Objetos o cosas del mundo real sobre los que guardamos datos (ej. Estudiante, Materia, Docente).

Atributos

Propiedades que describen a una entidad (ej. CI, Nombre, Fecha de Nacimiento).

Relaciones

Cómo interactúan entre sí (ej. Un Estudiante INSCRIBE una Materia).

Herencia de Tipos

Aprenderemos conceptos de Especialización y Generalización (Superclase y Subclases) para representar conceptos avanzados.

Unidad II

Transformación al Modelo Relacional y Reglas

Convertimos el diagrama gráfico (E-R) en esquemas de tablas reales con claves e integridad.

Las Claves (Keys)

• Clave Primaria (PK): Identificador único e irrepetible de cada fila (ej. Tu número de Carnet).

• Clave Foránea (FK): Conecta una tabla con otra para mantener la relación.

Reglas de Integridad

• De Entidad: La PK nunca puede ser nula.

• Referencial: Una FK debe existir previamente en la tabla de origen (evita datos huérfanos).

Unidad II

Normalización: El Arte del Orden

¿Qué es la Normalización?

Un proceso sistemático para descomponer tablas complejas y eliminar datos duplicados sin perder información.

1FN

Eliminar valores repetidos y asegurar atributos atómicos (indivisibles).

2FN y 3FN

Eliminar dependencias parciales y transitivas entre columnas.

4FN y 5FN

Niveles avanzados para casos especiales de multidependencias.

🔍 ¿Qué evitamos con la normalización?
Evitamos las temidas Anomalías de Actualización, Inserción y Eliminación. Por ejemplo: si cambias la dirección de un cliente, ¡solo debes actualizarla en un solo lugar y no en 500 filas!
Unidad III

SQL: Operaciones y Manipulación

SQL (Structured Query Language) es el estándar mundial para comunicarse con la Base de Datos.

Consultas Básicas y Avanzadas

Uso de SELECT, WHERE, filtros, ordenamiento y funciones de agrupación (SUM, AVG, COUNT).

Consultas Multi-Tabla (JOINs)

Aprenderemos a combinar 2 o más tablas de manera eficiente para generar reportes complejos.

Subconsultas y Vistas

Consultas anidadas dentro de otras y creación de tablas virtuales para simplificar la lectura de datos.

Unidad III

Lógica Programable y Seguridad

⚡ Objetos de Base de Datos

• Procedimientos y Funciones: Código guardado listo para ejecutarse en el servidor.

• Triggers (Disparadores): Acciones automáticas que se ejecutan cuando ocurre un evento (ej. Insertar un log de auditoría al borrar un registro).

🔒 Seguridad de la Información

• Gestión de Usuarios Administrativos.

• Definición de Roles y Privilegios (otorgar o denegar permisos de lectura o modificación).
