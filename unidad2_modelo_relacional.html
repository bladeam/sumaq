BAD 402 - Unidad II

El Modelo Relacional

Estructuras, Claves, Reglas de Integridad y Transformación E-R

🎯 Objetivo de la Unidad

Comprender la estructura formal del Modelo Relacional creado por E. F. Codd, sus reglas de integridad y cómo transformar un Modelo Entidad-Relación en tablas físicas.

💡 Idea Central: Toda la información del mundo real se representa organizándola estrictamente en tablas de dos dimensiones (Filas y Columnas).
Unidad II - Origen

1. Origen del Modelo Relacional

Propuesto por Edgar Frank Codd en 1970 en IBM.

¿Por qué revolucionó la industria?

Antes de 1970 se usaban modelos jerárquicos o en red muy complejos donde había que programar "rutas físicas" para buscar datos. Codd aportó una base matemática elegante basada en la teoría de conjuntos.

Unidad II - Conceptos

2. Definición de Relación (Tabla)

Una Relación es una tabla bidimensional compuesta por filas y columnas con características específicas:

Características Principales

• El orden de las filas no importa.

• El orden de las columnas no importa.

• No puede haber dos filas exactamente iguales.

Terminología Formal

• Tabla = Relación

• Fila = Tupla

• Columna = Atributo

Unidad II - Dominio

3. Atributos y Dominios

Atributo

Nombre de una columna que representa una propiedad de la entidad (ej: Precio, Stock).

Dominio

Conjunto de valores válidos y atómicos que un atributo puede tomar (ej: Dominio de Edad = Entero entre 0 y 120).

Ejemplo Sencillo: Si el dominio del atributo Fecha_Nacimiento es tipo 'FECHA', la BD rechazará intentar guardar el texto "Ayer".
Unidad II - Claves

4. Concepto de Claves (Keys)

Las claves permiten identificar registros y establecer conexiones relacionales entre tablas.

Superclave

Conjunto de uno o más atributos que identifican unívocamente una tupla.

Clave Candidata

Una superclave mínima (sin atributos sobrantes).

Clave Primaria (PK)

La clave candidata elegida por el diseñador.

Unidad II - Claves

5. Clave Primaria (Primary Key - PK)

Atributo Identificador Principal

Es la columna elegida para identificar de forma única e inconfundible cada fila de la tabla.

Ejemplo: En la tabla CLIENTES, el número de Cédula de Identidad (CI) es la PK. No pueden existir dos clientes con la misma cédula.
Unidad II - Claves

6. Clave Foránea (Foreign Key - FK)

Enlace entre Tablas

Es un atributo en una tabla que hace referencia a la Clave Primaria (PK) de otra tabla, estableciendo una relación formal.

Unidad II - Integridad

7. Regla 1: Integridad de Entidades

Ninguna Clave Primaria puede ser NULL

Dado que la PK se utiliza para identificar de forma única a cada tupla, no se permite que tenga un valor desconocido o nulo (NULL).

❓ ¿Por qué no puede ser NULL?
Si dos filas tuvieran PK en NULL, la base de datos no tendría forma de distinguirlas ni de saber a cuál hacer referencia en otras tablas.
Unidad II - Integridad

8. Regla 2: Integridad Referencial

Consistencia entre Relaciones

Un valor de Clave Foránea (FK) debe obligatoriamente coincidir con un valor existente de la Clave Primaria (PK) a la que apunta, o bien ser totalmente NULL.

Ejemplo de Violación: Intentar registrar un pedido para el Cliente_ID = 99 cuando en la tabla de Clientes el ID más alto es el 50.
Unidad II - Mapeo

9. Transformación Entidad-Relación a Relacional

El proceso de diseño pasa de un diagrama conceptual E-R a un esquema relacional lógico siguiendo reglas claras:

Paso 1: Entidades

Cada entidad regular se convierte en una Tabla.

Paso 2: Atributos

Los atributos pasan a ser Columnas de dicha tabla.

Unidad II - Mapeo

10. Mapeo de Relaciones 1:N (Uno a Muchos)

Regla para 1:N

La Clave Primaria del lado de la cardinalidad 1 pasa como Clave Foránea (FK) a la tabla del lado de cardinalidad N.

Ejemplo: Un DEPARTAMENTO tiene muchos EMPLEADOS.
Solución: Se agrega la columna Depto_ID (FK) dentro de la tabla EMPLEADO.
Unidad II - Mapeo

11. Mapeo de Relaciones N:M (Muchos a Muchos)

Regla para N:M

Se DEBE crear una nueva tabla intermedia (tabla de uniones) cuyas claves primarias serán las PKs de las dos entidades originales.

Ejemplo: ESTUDIANTE M:N MATERIA.
Solución: Se crea la tabla INSCRIPCION con (Estudiante_CI, Sigla_Materia) como PK compuesta.
Unidad II - Mapeo

12. Mapeo de Relaciones 1:1 (Uno a Uno)

Opción A: Propagación de Clave

Se coloca la PK de una entidad como FK en la otra (preferentemente en la que tiene participación total).

Opción B: Fusión de Tablas

Si ambas tienen participación total, se pueden unir en una sola tabla.

Unidad II - Atributos

13. Mapeo de Atributos Multivaluados

¿Qué hacer con un atributo que tiene varios valores?

No se pueden meter varios valores en una sola celda. Se debe crear una tabla independiente para ese atributo.

Ejemplo: Un cliente tiene 3 números de teléfono.
Tabla TELEFONOS_CLIENTE: (Cliente_CI [FK], Telefono)
Unidad II - Esquema

14. Representación del Esquema Relacional

Notación estándar de texto para describir la estructura del diseño:

Notación:
CLIENTE (CI, Nombre, Apellido, Email)
PEDIDO (ID_Pedido, Fecha, Total, Cliente_CI)

* Las subrayadas (CI) son PKs, las cursivas (Cliente_CI) son FKs.
Unidad II - SQL

15. Creación de Tablas en SQL Real

Traducción de nuestro esquema relacional al código DDL:

CREATE TABLE Cliente (
  ci INT PRIMARY KEY,
  nombre VARCHAR(50) NOT NULL
);
Unidad II - SQL

16. Definiendo Foreign Keys en SQL

CREATE TABLE Pedido (
  id_pedido INT PRIMARY KEY,
  fecha DATE,
  cliente_ci INT,
  FOREIGN KEY (cliente_ci) REFERENCES Cliente(ci)
);
