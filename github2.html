Guía Didáctica para Docentes

Estrategias de Uso de GitHub en Base de Datos

Guía integral con actividades, flujo colaborativo y estructura estándar de proyecto.

📌 1. Gestión de Proyectos de Base de Datos (Trabajos Integradores)

Los estudiantes documentan y versionan todo el ciclo de vida de un sistema de base de datos dentro de un repositorio estructurado:

  • Diagramas ER y Relacionales: Modelos conceptuales y lógicos en formato de imagen o mediante código incrustado en Markdown con Mermaid.js.
  • Scripts DDL y DML: Organización secuencial de scripts para creación de esquemas, cargas de datos de prueba, vistas e índices.
  • Diccionario de Datos: Documentación detallada en un archivo README.md sobre tablas, tipos de datos, llaves primarias/foráneas e integridad referencial.

📁 Estructura Estándar del Repositorio

Estructura recomendada que los estudiantes deben mantener en su proyecto final:

📁 mi-proyecto-bd/ ├── 📄 README.md <-- Alcance del proyecto, modelo ER y guía de ejecución ├── 📁 modelo/ │ ├── diagrama_er.png <-- Imagen o exportación del modelo Entidad-Relación │ └── diccionario_datos.md <-- Descripción técnica de tablas, campos y restricciones ├── 📁 sql/ │ ├── 01_crear_tablas.sql <-- DDL: CREATE TABLE, PK, FK, CHECK, UNIQUE │ ├── 02_insertar_datos.sql <-- DML: INSERT INTO (semillas / datos de prueba) │ ├── 03_consultas.sql <-- DML: Consultas SELECT, JOINs, agregaciones y reportes │ └── 04_procedimientos.sql <-- Vistas, Triggers, Stored Procedures y Funciones └── 📁 reportes/ └── optimizacion_indices.md <-- Análisis de rendimiento (EXPLAIN / EXPLAIN ANALYZE)
Carpeta / Archivo Tipo de Contenido Propósito Pedagógico
README.md Documentación Portada general del sistema, requisitos y guía de despliegue.
modelo/ Diseño Validación de la normalización (1FN, 2FN, 3FN) y diagramas lógicos.
sql/ Código SQL Garantiza la ejecución limpia y ordenada en cualquier SGDB.
reportes/ Análisis Demuestra la optimización mediante índices y análisis de ejecución.

⚡ 2. Automatización y Calificación con GitHub Classroom

Facilita la distribución y evaluación continua de prácticas de laboratorio:

  • Asignación automática: Generación de repositorios individuales o grupales a partir de una plantilla docente.
  • Autograding (Calificación Automatizada): Configuración de GitHub Actions con contenedores Docker (PostgreSQL, MySQL o SQLite) para ejecutar pruebas automáticas sobre las consultas SQL del alumno.

🗃️ 3. Banco de Problemas y Datasets (Cátedra Abierta)

Central de recursos centralizada en un repositorio público del curso:

  • Datasets Reales: Publicación de archivos .sql o .csv con volúmenes de datos reales (e-commerce, hospitales, finanzas) para prácticas de Fork/Clone.
  • Jupyter Notebooks con Kernel SQL: Guías interactivas clasificadas por nivel (JOINs, Subconsultas, Agregaciones, Transacciones) ejecutables directamente en GitHub.

👥 4. Simulación de Trabajo en Equipo (Flujo de Trabajo Real)

Implementación de metodologías ágiles y control de versiones en equipo:

  • Gestión con Issues y GitHub Projects: Creación de tableros Kanban para asignar tareas (ej. "Crear trigger de auditoría", "Optimizar consulta X").
  • Pull Requests y Code Review: Prohibición de commits directos a main. Obliga a revisiones de código SQL entre compañeros antes de la integración.

🌐 5. Publicación y Web (GitHub Pages)

Aprovechamiento del servicio de hosting estático gratuito para la materia:

  • Portal de la Asignatura: Publicación de cronogramas, sílabo, guías de laboratorios y recursos.
  • Documentación Interactiva: Portal web de modelos de datos utilizando generadores de sitios estáticos como MkDocs o Docusaurus.
💡 Sugerencia Docente: Exigir el enlace de GitHub Pages en el README.md para revisar la documentación de los proyectos finales de forma interactiva.
