Unidad I - Antecedentes

1. Archivos Tradicionales vs. Bases de Datos

📁 Archivos Tradicionales

Cada aplicación guardaba sus propios datos en archivos independientes (ej. TXT, CSV, Excel).

Problemas: Datos duplicados, falta de sincronización y dificultad para compartir información.

🗄️ Base de Datos

Colección integrada y compartida de datos lógicamente relacionados con acceso centralizado.

Ventajas: Única fuente de verdad, consistencia e integración.

Unidad I - Conceptos

2. Organización de Registros y Campos

Los datos se estructuran de forma jerárquica para facilitar su procesamiento:

Campo (Atributo)

La unidad mínima de información. Ej: Nombre, Edad.

Registro (Tupla)

Conjunto de campos relacionados que describen un elemento. Ej: Carlos, 21 años, Ing. Sistemas.

Archivo / Tabla

Colección de registros del mismo tipo.

Ejemplo en Excel: Una fila es un Registro, una columna es un Campo, y la hoja completa es la Tabla.
Unidad I - Organización

3. Sistemas de Información en las Organizaciones

Una Base de Datos es el corazón de un Sistema de Información (SI) empresarial.

Sistemas Operacionales (OLTP)

Registran transacciones del día a día rápidamente. Ej: Ventas en un supermercado, transferencias bancarias.

Sistemas Analíticos (OLAP)

Analizan datos históricos para la toma de decisiones gerenciales. Ej: Reporte de tendencias de ventas anuales.

Unidad I - SGBD

4. ¿Qué es un SGBD / DBMS?

Sistema de Gestión de Bases de Datos

Es el software especializado que sirve de interfaz entre los usuarios/aplicaciones y los datos físicos almacenados.

Analogía: El SGBD es como el mozo de un restaurante: tú le pides el menú (consulta) y él va a la cocina (servidor) y te trae exactamente lo que pediste sin que entres a cocinar.
Ejemplos Populares: PostgreSQL, MySQL, Oracle, SQL Server, SQLite.
Funciones clave: Seguridad, concurrencia, respaldo y optimización.
Unidad I - SGBD

5. Importancia del SGBD en la Empresa

Manejo de Concurrencia

Permite que miles de usuarios compren en un sitio e-commerce al mismo tiempo sin colisionar.

Recuperación de Fallas

Si se corta la luz a mitad de una transacción, el SGBD deshace el cambio inconcluso para no corromper datos.

🔍 Haz clic para ver qué pasa sin SGBD
Sin un SGBD, dos usuarios podrían sobrescribir el mismo archivo al mismo tiempo, borrando la información del otro usuario permanentemente.
Unidad I - Arquitectura

6. Independencia de Datos

Es la capacidad de modificar el esquema en un nivel sin alterar el esquema del nivel superior.

Independencia Física

Cambiar el disco duro o la forma de almacenamiento sin cambiar los programas o tablas.

Independencia Lógica

Agregar un nuevo campo a una tabla sin romper las aplicaciones existentes que no usan ese campo.

Unidad I - SGBD

7. Tipos de Usuarios de BD

Administrador (DBA)

Controla el acceso, seguridad, rendimiento y respaldos.

Diseñador / Programador

Crea las tablas, modelos y escribe las consultas SQL.

Usuario Final

Usa las aplicaciones web o móviles sin saber cómo funciona la BD por dentro.

Unidad I - Arquitectura

8. Arquitectura de 3 Niveles ANSI-SPARC

Estándar que divide el sistema de base de datos en tres niveles de abstracción:

1. Nivel Externo (Vistas): Cómo ven los usuarios los datos.
2. Nivel Conceptual: Estructura lógica completa (tablas y relaciones).
3. Nivel Interno (Físico): Archivos, índices y bloques en disco.
Unidad I - Lenguajes

9. Lenguajes de BD: DDL y DML

DDL (Data Definition Language)

Define y modifica las estructuras del sistema.

Comandos: CREATE, ALTER, DROP.

DML (Data Manipulation Language)

Permite manipular y consultar los datos dentro de las estructuras.

Comandos: SELECT, INSERT, UPDATE, DELETE.

Unidad I - SGBD

10. Diccionario de Datos

Metadatos: "Datos sobre los Datos"

El diccionario de datos almacena la información sobre la propia estructura de la BD: nombres de tablas, tipos de datos, permisos y restricciones.

Ejemplo: Registra que la columna Edad debe ser un número entero y no puede ser negativa.

Unidad I - Teoría

13. ¿Qué es el Álgebra Relacional?

Base Matemática

Es un lenguaje de consulta procedimental teórico. Toma una o varias relaciones (tablas) como entrada y produce una nueva relación como resultado.

Es el fundamento sobre el cual funciona el lenguaje SQL.

Unidad I - Álgebra Relacional

14. Operador Selección (σ - Sigma)

Selecciona filas (tuplas) que cumplen con una condición específica.

Ejemplo: σ Edad > 18 (Estudiantes)
Resultado: Muestra únicamente a los estudiantes mayores de edad.
Unidad I - Álgebra Relacional

15. Operador Proyección (π - Pi)

Filtra y selecciona columnas (atributos) específicas, eliminando las demás.

Ejemplo: π Nombre, Carrera (Estudiantes)
Resultado: Muestra solo las columnas de Nombre y Carrera, ignorando CI, Edad y Dirección.
Unidad I - Álgebra Relacional

16. Unión (∪) e Intersección (∩)

Unión (∪)

Combina todas las tuplas de dos tablas compatibles eliminando duplicados.

Ej: Lista de alumnos de Turno Mañana ∪ Turno Noche.

Intersección (∩)

Muestra solo las tuplas que existen en AMBAS tablas.

Ej: Alumnos inscritos en Matemáticas ∩ Física.

Unidad I - Álgebra Relacional

17. Diferencia (−) y Producto Cartesiano (×)

Diferencia (−)

Tuplas en la primera tabla que NO están en la segunda.

Ej: Clientes que han comprado − Clientes que devolvieron productos.

Producto Cartesiano (×)

Combina cada fila de la primera tabla con TODAS las filas de la segunda.

Unidad I - Práctica

18. Ejemplo Integrador de Álgebra Relacional

Consulta requerida: "Obtener los nombres de los estudiantes de la carrera de Sistemas."

Expresión Álgebra Relacional:
π Nombre ( σ Carrera = 'Sistemas' ( Estudiantes ) )
💡 Explicación paso a paso
1. Primero se evalúa lo interno: σ Carrera = 'Sistemas' filtra las filas dejando solo estudiantes de Sistemas.
2. Luego la proyección externa: π Nombre extrae únicamente la columna con sus nombres.
